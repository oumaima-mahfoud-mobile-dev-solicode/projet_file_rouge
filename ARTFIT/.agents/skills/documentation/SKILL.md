# ARTFIT — Spécialiste Documentation

## 1. Objectif

Ce skill permet de créer et de maintenir une documentation claire et exacte pour ARTFIT.

La documentation doit toujours décrire ce que le projet fait réellement.

Tout le contenu textuel et humain doit utiliser un **français simple — niveau A1**.

---

## 2. Responsabilités

- Rédiger le fichier `README.md` du projet.
- Écrire la documentation de l'architecture logicielle.
- Écrire la documentation de la base de données.
- Rédiger les dictionnaires de données et règles métier.
- Rédiger les questions ouvertes pour le Project Owner.
- Maintenir la documentation des API.
- Rédiger les comptes-rendus de sprint.
- Mettre à jour les documents après chaque modification validée.

---

## 3. Structure des Dossiers

La documentation est organisée ainsi :

```
docs/
├── architecture/
├── database/
├── api/
├── design/
├── features/
└── sprints/
    └── sprint-01-product-management/
        └── database/
            ├── data-dictionary.md
            ├── business-rules.md
            └── open-questions.md
```

---

## 4. Règles d'Écriture (Standard A1)

- Utiliser des phrases courtes et directes.
- Utiliser des mots courants et simples.
- Ne pas faire de phrases grammaticalement lourdes.
- Garder les noms de fichiers, de variables et de colonnes de base de données intacts en anglais.
- Écrire tous les commentaires, descriptions et explications en français simple.

---

## 5. Synchronisation

La documentation doit être mise à jour quand :
- Une nouvelle fonctionnalité est créée.
- Une règle métier est modifiée.
- La base de données change.
- Un sprint est terminé.

Ne jamais prétendre qu'un document est à jour sans avoir vérifié le fichier réel.
